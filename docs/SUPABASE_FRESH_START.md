# Supabase fresh start for Reyeltor-uz

Your old project (`oudfimhywevcpqfimpbm`) no longer exists. Follow these steps once.

## 1. Create a new Supabase project

1. Open [supabase.com/dashboard](https://supabase.com/dashboard)
2. Use **Simple solutions** (or any org you prefer)
3. **New project** → name it `reyeltor-uz`
4. Choose region **Singapore (ap-southeast-1)** or closest to Uzbekistan
5. Wait until status is **Active** (not “Coming up…”)

## 2. Copy API keys into `.env`

Dashboard → **Project Settings → API**

```bash
EXPO_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=your_anon_public_key
```

Replace the dead `oudfimhywevcpqfimpbm` values completely.

## 3. Run database SQL

Dashboard → **SQL Editor → New query**

1. Paste all of **`supabase/schema.sql`** → **Run**
2. Paste all of **`supabase/storage-setup.sql`** → **Run**
3. Paste all of **`supabase/patch-saved-searches-v1.sql`** → **Run** (server-side coins, saved searches, match alerts)
4. Paste all of **`supabase/patch-listing-integrity-v1.sql`** → **Run** (duplicate detection at publication)
5. Paste all of **`supabase/patch-seller-tools-v1.sql`** → **Run** (listing performance statistics)
6. Paste all of **`supabase/patch-privacy-v1.sql`** → **Run** (sellers' hidden phone numbers stay private)
7. Paste all of **`supabase/patch-freshness-v1.sql`** → **Run** ("Confirmed X days ago", availability reminders, expiry archiving)

**Shortcut for steps 3–7:** paste **`supabase/apply-all-v1.sql`** once (generated by
`node scripts/build-v1-patch-bundle.mjs`; it runs all five `-v1` patches in order inside one transaction).

You should see tables: `users`, `listings`, `listing_photos`, `favorites`, `saved_searches`, etc.

> **Order matters:** the `-v1` patches must run **after** every older patch, in the order above. The older `patch-existing.sql` /
> `apply-missing-patches.sql` re-create permissive policies (e.g. client-side coin and check-in writes).
> If you ever re-run one of them, run the `-v1` patches again afterwards. They are safe to re-run.
>
> Then deploy the `saved-search-alerts` edge function and its two schedules — see `supabase/functions/README.md`.

## 4. Configure Auth

Dashboard → **Authentication → URL configuration**

| Field | Value |
|--------|--------|
| Site URL | `https://reyeltor.uz` |
| Redirect URLs | `reyeltor://auth/reset-password` |

Dashboard → **Authentication → Providers → Email**

For easier testing during development, you can **disable “Confirm email”**.  
For production, keep it on and confirm your inbox after registering.

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| “Cannot reach the Reyeltor server” | Wrong URL in `.env`, or project still starting |
| “Email yoki parol noto'g'ri” with correct password | Email not confirmed yet, or wrong project keys |
| Reset password email never arrives | Check spam; add redirect URL; confirm Auth email settings |
| Photo upload fails | Re-run `storage-setup.sql` |
| `verify-supabase.mjs` fails on tables | Re-run `schema.sql` |
